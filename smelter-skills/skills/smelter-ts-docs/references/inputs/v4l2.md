# V4L2 input (Video for Linux 2)

**Experimental.** Captures video using the Video for Linux 2 API. Devices live at paths like `/dev/video[N]`, `/dev/v4l/by-id/[DEVICE ID]`, or `/dev/v4l/by-path/[PCI/USB PATH]`.

**Availability:** Node.js · Browser (Client)

> **Note:** Supported image formats are `YUYV` and `NV12`. Check what your device supports with `v4l2-ctl -d [DEVICE PATH] --list-formats-ext`.

## Usage

```tsx
import Smelter from "@swmansion/smelter-node";

const smelter = new Smelter();
await smelter.init();
await smelter.registerInput("example", {
  type: "v4l2",
  path: "/dev/video0",
  format: "yuyv",
  resolution: { width: 1920, height: 1080 },
  framerate: 30,
});
```

## Type

```tsx
type RegisterV4l2Input = {
  type: "v4l2";
  path: string;
  format: "yuyv" | "nv12";
  resolution: {
    width: number;
    height: number;
  };
  framerate: number | string;
  required?: boolean;
  sideChannel?: SideChannel;
};
```

## Properties

### path
Path to the V4L2 device.
- **Type**: `string`

---

### format
Video capture format.
- **Type**: `"yuyv" | "nv12"`
- **Values**:
  - `yuyv` — YUYV, interleaved 4:2:2 YUV.
  - `nv12` — NV12, planar 4:2:0 YUV (one Y plane, one interleaved UV plane).

---

### resolution
Capture resolution. The driver may adjust this to the closest resolution supported at the selected format.
- **Type**: `{ width: number; height: number }`

---

### framerate
Video framerate. The driver may adjust this to the closest framerate supported at the selected format and resolution. Either a u32 or a string in `"NUM/DEN"` fraction form.
- **Type**: `number | string`

---

### required
If true and the stream is delayed, Smelter postpones output frames until the stream is received.
- **Type**: `boolean`
- **Default**: `false`

---

### sideChannel
Enable side channel publishing for this input. The external consumer reads decoded frames/audio from a Unix socket under `SMELTER_SIDE_CHANNEL_SOCKET_DIR`.
- **Type**: `SideChannel` (see below)
- **Availability**: Node.js

## SideChannel

Per-track side channel configuration. Controls how decoded data is exposed for external consumption.

```tsx
type SideChannel = {
  video?: boolean;
  audio?: boolean;
  delayMs?: number;
};
```

### video
Publish decoded RGBA video frames for this input on the side channel.
- **Type**: `boolean`
- **Default**: `false`

### audio
Publish decoded PCM audio batches for this input on the side channel.
- **Type**: `boolean`
- **Default**: `false`

### delayMs
Side channel delay in ms. Frames are buffered this far ahead of when the queue consumes them, so the subscriber receives them early and has roughly this much time to process before the frame is due.
- **Type**: `number`
- **Default**: `0`
